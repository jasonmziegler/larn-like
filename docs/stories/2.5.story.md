# Story 2.5: Monster Evolution History Display

## Status
done

## Story
**As a** player encountering evolved monsters,
**I want** to see their kill history and trophy equipment,
**so that** I understand the story behind each monster and can strategically prepare for enhanced encounters.

## Acceptance Criteria
1. Monster inspection panel shows kill count and victim names (e.g., "Skeleton - Slayer of 3 Heroes")
2. Trophy equipment list displays items taken from defeated heroes with original names
3. Enhanced stats clearly indicate bonuses gained from previous victories
4. Monster descriptions differentiate evolved monsters from baseline dungeon creatures
5. History information is paginated appropriately for monsters with extensive kill records
6. Visual indicators (color, symbols) distinguish evolved monsters on the main game screen

## Dev Notes

### Current Monster Display

**Adjacent monster info** (`GameHUD.ts:31-37`):
```typescript
public renderAdjacentMonster(monster: Monster | null, row: number): void {
  if (!monster) return;
  const hpColor = getMonsterHpColor(monster);
  const hpText = `${monster.char} ${monster.name} HP:${monster.health}/${monster.maxHealth}`;
  this.renderer.drawText(hpText, 2, row, hpColor);
}
```

This currently shows only the basic info. Story 2.5 enriches this for evolved monsters while keeping baseline monsters compact.

**Map rendering** (`main.ts:308-320`): Monsters render with `monster.char` and `monster.color` at viewport-relative positions. Evolved monsters need a different color to stand out visually.

### Layout Constraints

The screen is 80 columns x 30 rows:
- Row 0: Top border
- Row 1: Status bar
- Row 2: Adjacent monster info (single line — keep concise)
- Rows 3-23: Map area (bordered)

### Evolved Color Strategy

**Color-only visual distinction** — ASCII character remains the same, only color changes:
- **Evolution 0 (baseline):** Original base color (e.g., `#00FF00` for goblins)
- **Evolution 1 (Veteran):** Bright yellow `#FFFF00`
- **Evolution 2 (Elite):** Bright orange `#FF8800`
- **Evolution 3+ (Legendary):** Bright red `#FF0000`

This approach:
- Keeps bestiary unlimited (no character conflicts)
- Maintains traditional roguelike aesthetics
- Provides clear visual escalation
- Works well with color-based player feedback

Implementation can use a simple lookup. Since the canvas renderer uses hex color strings, define a small mapping:

```typescript
function getEvolvedColor(baseColor: string, evolutionLevel: number): string {
  if (evolutionLevel <= 0) return baseColor;
  if (evolutionLevel === 1) return '#FFFF00'; // yellow - Veteran
  if (evolutionLevel === 2) return '#FF8800'; // orange - Elite
  return '#FF0000'; // red - Legendary (3+)
}
```

**Important:** The character itself (e.g., `g` for goblin) never changes — only its render color.

### Inspection Panel Pattern

Follow the `InventoryPanel` pattern (`apps/web/src/ui/InventoryPanel.ts`):
- Class with `render()` method that draws on the CanvasRenderer
- Toggled by a key press in main.ts
- Stored as a nullable reference (null = closed)
- Suppresses other input while open
