## Dev Notes

### Previous Story Insights
No previous story exists - this is the foundation story for the entire project.

### Technology Stack
[Source: architecture/tech-stack.md]
- **Frontend Language**: TypeScript 5.3+ for type-safe client-side game logic
- **Frontend Framework**: Vanilla TypeScript ES2022+ for pure Canvas 2D game rendering
- **Backend Language**: TypeScript 5.3+ for serverless function development
- **Backend Framework**: Vercel Functions for serverless API endpoints
- **Build Tool**: Vite 5+ for frontend build and dev server with fast HMR
- **Bundler**: Rollup (via Vite) for production bundle optimization
- **Testing**: Vitest for both frontend and backend unit testing
- **CI/CD**: GitHub Actions for automated testing and deployment

### Project Structure Requirements
[Source: architecture/unified-project-structure.md]
```
larn-like/
├── .github/workflows/          # CI/CD workflows
├── apps/
│   ├── web/                   # Frontend application
│   │   ├── src/
│   │   │   ├── rendering/     # Canvas rendering system
│   │   │   ├── core/          # Game engine
│   │   │   └── types/         # Type definitions
│   │   ├── public/            # Static assets
│   │   └── package.json
│   └── api/                   # Backend application
│       ├── src/
│       │   └── shared/        # Shared backend utilities
│       └── package.json
├── packages/
│   ├── shared/                # Shared types/utilities
│   └── config/                # Shared configuration
└── package.json               # Root package.json
```

### Canvas Rendering Architecture
[Source: architecture/frontend-architecture.md]
- **CanvasRenderer.ts**: Main rendering coordinator located in `apps/web/src/rendering/`
- **ASCIIAtlas.ts**: Character sprite management for ASCII characters
- **ColorManager.ts**: Green intensity system for authentic terminal aesthetic
- **Canvas 2D Context**: HTML5 Canvas with 2D rendering context for 60fps ASCII rendering

### Build and Development Configuration
[Source: architecture/tech-stack.md]
- **Vite Configuration**: Fast HMR for game development iteration with TypeScript support
- **Development Server**: Hot reload for rapid development cycles
- **Production Bundling**: Tree shaking for minimal bundle size optimization
- **TypeScript**: ES2022+ target with strict type checking across monorepo

### Testing Requirements
[Source: architecture/testing-strategy.md]
- **Frontend Tests**: Located in `apps/web/tests/` with unit, integration, and e2e directories
- **Testing Framework**: Vitest for consistent testing stack across frontend/backend
- **Canvas Mocking**: Use canvas mock utilities for testing rendering components
- **Test Structure**: Unit tests for components/core, integration tests for services, e2e tests for full gameplay

### Coding Standards
[Source: architecture/coding-standards.md]
- **Type Sharing**: Always define types in packages/shared and import from there
- **Environment Variables**: Access only through config objects, never process.env directly
- **File Naming**: PascalCase for components, camelCase for utilities, kebab-case for API routes
- **Error Handling**: All functions must use standard error handling patterns

### CI/CD Pipeline Requirements
[Source: architecture/backend-architecture.md]
- **GitHub Actions**: Automated testing and deployment workflows
- **Vercel Integration**: Seamless deployment for serverless functions
- **Testing Pipeline**: Run Vitest tests for both frontend and backend
- **Build Verification**: Ensure TypeScript compilation succeeds across all packages

### Testing

**Test File Locations:**
[Source: architecture/testing-strategy.md]
- Frontend unit tests: `apps/web/tests/unit/`
- Frontend integration tests: `apps/web/tests/integration/`
- Backend unit tests: `apps/api/tests/unit/`

**Testing Frameworks and Patterns:**
- **Vitest**: Primary testing framework for both frontend and backend
- **Canvas Mocking**: Use `mockCanvas()` utility for testing Canvas 2D rendering
- **Component Testing**: Test individual components and utilities in isolation
- **Integration Testing**: Test service layer integration with mocked dependencies

**Specific Testing Requirements for this Story:**
- Test TypeScript compilation across all packages
- Test Canvas 2D context initialization and basic ASCII character rendering
- Test development server startup and hot reload functionality
- Test build process produces working production bundles
- Verify shared types can be imported correctly from packages/shared/
