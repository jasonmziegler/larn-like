<!-- Context: Brownfield enhancement - formalizing existing main.ts prototype into modular systems -->

## Story
**As a** player,
**I want** to explore larger dungeon levels with a scrolling viewport and encounter diverse monsters,
**so that** the dungeon feels expansive and each run presents varied challenges.

## Acceptance Criteria
1. Dungeon generation logic is extracted from main.ts into a dedicated DungeonGenerator module
2. Dungeon levels can be larger than the visible viewport (e.g., 120x40 tiles)
3. Viewport scrolls to follow the player, keeping the hero near center of screen
4. At least 3 distinct monster types spawn in dungeons with varied stats and ASCII characters
5. Monster spawning logic uses all available monster definitions with depth-appropriate distribution
6. Existing movement, collision, and rendering functionality continues to work unchanged
7. Numpad movement keys (8/2/4/6 and diagonals 7/9/1/3) are supported alongside WASD/arrows

## Dev Notes

### Existing Implementation (Brownfield Context)
The current `main.ts` contains inline implementations of:
- `generateDungeon()` - Creates 78x20 dungeon with 4-6 rooms and corridors
- `findEmptySpot()` - Finds unoccupied floor tiles for entity placement
- `render()` - Draws all tiles directly (no viewport offset)
- Monster spawning in `initGame()` - Only uses GOBLIN and ORC

**What exists and must NOT be broken:**
- Movement via WASD/arrows in the keydown handler
- Wall and monster collision detection in `tryMove()`
- Monster AI movement in `moveMonsters()`
- Combat triggering on monster collision
- Item pickup system
- GameHUD status bar rendering
- Title screen → naming screen → game flow

**What this story adds:**
- Module extraction (DungeonGenerator.ts)
- Larger dungeon dimensions with viewport scrolling
- 3+ monster type spawning
- Numpad movement support

### Viewport Implementation Approach
The viewport should work as a simple camera offset:
```typescript
// In game state
cameraX: number; // top-left corner of visible area
cameraY: number;

// Viewport dimensions (visible area within the border)
const VIEWPORT_COLS = 78; // DUNGEON_WIDTH stays as render viewport
const VIEWPORT_ROWS = 20; // DUNGEON_HEIGHT stays as render viewport

// Camera follows hero with clamping
cameraX = clamp(heroPos.x - VIEWPORT_COLS/2, 0, dungeonWidth - VIEWPORT_COLS);
cameraY = clamp(heroPos.y - VIEWPORT_ROWS/2, 0, dungeonHeight - VIEWPORT_ROWS);

// Render only visible tiles
for (y = cameraY; y < cameraY + VIEWPORT_ROWS; y++)
  for (x = cameraX; x < cameraX + VIEWPORT_COLS; x++)
    drawChar(tile, x - cameraX + 1, y - cameraY + 1, color);
```

### Testing Patterns
- **Environment**: `// @vitest-environment jsdom` at file top
- **Mock Renderer**: Object literal with `vi.fn()` methods cast as `unknown as CanvasRenderer`
- **Vitest**: Primary framework, matches existing test structure

### Performance Requirements
- 60fps rendering with viewport culling (only draw visible tiles)
- Instant movement response
- No perceptible lag from larger dungeon dimensions
