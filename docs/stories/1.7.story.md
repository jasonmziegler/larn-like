## Story
**As a** player,
**I want** a clear, organized game interface with dedicated areas for status, combat log, and monster information,
**so that** I can understand the current game state without text overlapping or information being lost.

## Acceptance Criteria
1. Canvas expands from 80x24 to 80x30 with dedicated panel regions
2. Dedicated status bar displays HP, ATK, DEF, Teeth cleanly without overlap
3. Adjacent monster info displays in a dedicated area separate from the map border
4. Action log panel below the map shows at least 5 scrollable message lines
5. Map viewport (78x20) continues to render correctly with border
6. All existing functionality (movement, combat, title screen, naming) works unchanged
7. Canvas scales appropriately in the browser window

### Front-End Spec Reference
The front-end spec (`docs/front-end-spec/wireframes-mockups.md`) defines an 80x40 multi-panel target layout. This story implements an **incremental step** toward that spec - expanding to 80x30 with status bar and action log. The full 80x40 layout with right-side panels (View Panel, Inventory) is deferred to Epic 3.

### Box Drawing Approach Note
The dev should determine whether the status bar and monster info rows sit **inside** the dungeon border box or **above** it. Both approaches work - the hard constraint is: 20-row map viewport + 6-line action log + status row + monster info row = 30 rows total. Choose whichever looks best visually.

Note that both `TitleScreen.ts` and `CharacterNamingScreen.ts` call `drawBox(0, 0, VIEWPORT_WIDTH, VIEWPORT_HEIGHT)`. Changing `VIEWPORT_HEIGHT` to 30 will automatically expand their borders, but the content inside will NOT re-center - see hardcoded row values below.

### Hardcoded Row Values in UI Screens
These screens have hardcoded row positions that were centered for 24-row canvas and will need re-centering for 30-row canvas:

**TitleScreen.ts:**
- Title ASCII art: row 2 (startRow)
- Subtitle: row 9
- INSERT COIN prompt: row 12
- Credits counter: row 15
- Instructions: rows 18 and 20
- drawBox uses `VIEWPORT_HEIGHT` (auto-expands)

**CharacterNamingScreen.ts:**
- Title "NAME YOUR HERO": row 6
- Input field: row 11
- Character count: row 13
- Error message: row 15
- Instructions: row 18
- drawBox uses `VIEWPORT_HEIGHT` (auto-expands)

### Constants to be aware of
- `GAME_CONSTANTS.VIEWPORT_WIDTH` = 80 (used by CanvasRenderer)
- `GAME_CONSTANTS.VIEWPORT_HEIGHT` = 24 (used by CanvasRenderer - needs update)
- `VIEWPORT_COLS` = 78 in main.ts (dungeon map columns inside border)
- `VIEWPORT_ROWS` = 20 in main.ts (dungeon map rows inside border)
