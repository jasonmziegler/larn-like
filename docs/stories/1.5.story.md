## Story
**As a** player,
**I want** combat with automatic defend/evade mechanics and flee-on-disengage, with detailed results in the message log,
**so that** combat feels fluid within the bump-to-attack model while providing tactical feedback.

## Acceptance Criteria
1. Combat logic is extracted from main.ts into a dedicated Combat module
2. Bump-to-attack auto-resolves: hero attacks, monster retaliates with evade and block rolls applied automatically
3. Moving away from an adjacent monster triggers an automatic flee roll
4. All combat actions produce detailed message log entries (damage dealt, evaded, blocked, damage reduced, flee success/failure)
5. Monster health bars or HP indicators are visible when adjacent to a monster
6. Monster death drops a type-specific reagent item in addition to teeth
7. Existing movement, monster AI, and death handling continue to work unchanged
8. Monster attack messages use type-specific verbs (e.g., "claws", "smashes", "bites")

## Dev Notes

### Existing Implementation (Brownfield Context)
The current `main.ts` contains inline `combat()` function:
- Bump-to-attack: moving into a monster triggers combat
- Hero attacks first: `Math.max(1, heroAtk - monster.defense + random(0-4))`
- Monster retaliates: `Math.max(1, monster.attack - heroDef + random(0-2))`
- Monster death: splice from array, drop 1-5 teeth, victory check
- Hero death: `applyDamage()`, isAlive check, game over message
- Uses `getEffectiveAttack(hero)` and `getEffectiveDefense(hero)` from Hero.ts

**What exists and must NOT be broken:**
- Bump-to-attack mechanic (moving into monster = combat)
- Damage calculation using hero/monster stats
- Monster removal on death
- Teeth drops on monster kill
- Hero death detection and game over flow
- Victory condition (all monsters killed)
- Combat messages in `state.messages`

**What this story adds:**
- Combat module extraction
- Automatic evade/block rolls on monster retaliation
- Flee-on-disengage when moving away from adjacent monster
- Adjacent monster HP display
- Reagent item drops
- Monster-type-specific attack verbs

### Combat Model Design (Bump-Driven, No Combat Mode)
There is NO explicit combat mode. All combat is implicit:
- **Attack:** Hero bumps into monster -> auto-resolve attack exchange
- **Defend:** Automatic evade/block rolls on every monster retaliation
- **Flee:** Hero moves away from adjacent monster -> auto-resolve flee roll

No `inCombat` or `combatTarget` state needed. No combat prompt UI. The existing turn-based bump model is preserved; this story adds defensive rolls and flee mechanics on top of it.

```typescript
// NO changes to GameState for combat mode
// Combat is stateless - resolved entirely within processCombat()

interface CombatResult {
  damageDealt: number;
  damageReceived: number;
  evaded: boolean;
  blocked: boolean;
  blockReduction: number;
  monsterKilled: boolean;
  heroKilled: boolean;
  messages: string[];
}

// Flee is handled in tryMove() when moving away from adjacent monster
interface FleeResult {
  success: boolean;
  damageReceived: number;  // 0 if success, free attack damage if fail
  messages: string[];
}
```

```typescript
}
```
