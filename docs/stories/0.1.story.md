# Story 0.1: Supabase Account Setup & API Configuration

## Status
Draft

## Story
**As a** developer,
**I want** a properly configured Supabase account with all necessary services enabled,
**so that** I can develop and test the game with persistent world state without infrastructure delays.

## Acceptance Criteria
1. Supabase account created with appropriate plan selection for development and production
2. PostgreSQL database provisioned with proper configuration for game data
3. Authentication service enabled with email/password and optional OAuth providers
4. API keys generated and documented for both public (anon) and service role access
5. Real-time subscriptions enabled for world state synchronization
6. Storage buckets created for any game assets or save data if needed

### Supabase Service Requirements

- **Database**: Supabase PostgreSQL 15+ for persistent world state storage

- **File Storage**: Supabase Storage for static assets and save files

### Complete Database Schema
[Source: architecture/database-schema.md]
The database schema includes the following critical tables:
- **players**: Authentication integration with auth_id field linking to Supabase Auth
- **heroes**: Temporary progression data that resets on death
- **equipment_items**: Named equipment with blessing support ("Sarah's Iron Sword" format)
- **monsters**: Individual monster instances with evolution tracking
- **dungeon_levels**: Procedurally generated dungeon floors with JSONB layout data
- **soul_shrines**: Blessing stations created from hero deaths
- **death_events**: Immutable event sourcing records for world consequences

### Row Level Security (RLS) Policies
[Source: architecture/infrastructure-setup-configuration.md]
Critical security policies to implement:
- **Players**: Can only access own data using `auth.uid()::text = auth_id`
- **Heroes**: Restricted to player's own heroes via player_id relationship
- **World Data**: Readable by all authenticated users (monsters, dungeon_levels)
- **Equipment**: Ownership restrictions based on original_owner field
