# Story 2.3: Trophy Equipment Transfer System

## Status
Done

## Story
**As a** player,
**I want** monsters that kill heroes to acquire the deceased hero's equipped items as trophies,
**so that** promoted monsters become more dangerous and carry visible reminders of past victories.

## Acceptance Criteria
1. When hero dies, all equipped items (dagger, armor, etc.) transfer to the killing monster
2. Monster equipment slots accommodate transferred items within the 10-slot constraint system
3. Promoted monsters display equipped trophy items in their detail panel descriptions
4. Trophy equipment provides appropriate stat bonuses to the promoted monster
5. Equipment overflow (when monster slots are full) gets distributed to nearby dungeon chests
6. Trophy equipment retains any naming or legacy information from previous heroes

## Dev Notes

### Existing Equipment System

**Equipment.ts** (`apps/web/src/game/Equipment.ts`) provides:
- `createEmptySlots()` -- returns EquipmentSlots with all 10 slots null
- `getEquippedItems(slots)` -- returns array of non-null equipped items
- `getTotalAttackBonus(slots)` / `getTotalDefenseBonus(slots)` -- sum stat bonuses
- `isSlotOccupied(slots, slot)` -- check if a slot is taken

**EquipmentItem interface** (from `packages/shared/src/types/hero.types.ts`):
```typescript
interface EquipmentItem {
  id: string;
  name: string;        // e.g., "Sarah's Dagger" -- preserves owner name
  slot: EquipmentSlotType;
  attackBonus: number;
  defenseBonus: number;
  description: string;
}
```

**10 slots:** weapon, offHand, helmet, bodyArmor, gloves, boots, ring1, ring2, amulet, belt

### Transfer Logic

Equipment transfer is slot-matched: the hero's weapon goes to the monster's weapon slot, bodyArmor to bodyArmor, etc. If the monster already has an item in that slot (from a previous hero kill), the new item overflows to a dungeon chest.

For monsters that have killed multiple heroes across multiple promotions, equipment can accumulate. The 10-slot system naturally caps this.

### Monster Combat with Equipment

Currently `Combat.ts:processCombat()` uses raw `monster.attack` and `monster.defense`. After this story, monster effective stats should include equipment bonuses:
- Effective attack = `monster.attack + getTotalAttackBonus(monster.equipment)`
- Effective defense = `monster.defense + getTotalDefenseBonus(monster.equipment)`

### Dungeon Chests

Chests are a new entity type. They need to:
- Be stored in the dungeon level data (alongside monsters and teeth)
- Render on the map with a distinct ASCII character
- Be interactable (pickup items) -- but full chest interaction UI is Epic 3 scope (Story 3.3). For now, just place the chest and persist it. Pickup can be deferred.
