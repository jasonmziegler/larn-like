## Status

## Story
**As a** player starting a new game,
**I want** to name my hero character on a dedicated naming screen,
**so that** my hero feels personal and the name carries through to equipment, stats display, and gameplay identity.

## Acceptance Criteria
1. After pressing Enter on the title screen (with credits), a character naming screen appears
2. Player can type a hero name using keyboard input, displayed as green ASCII text on screen
3. Name is limited to 12 characters maximum with only alphanumeric characters and spaces allowed
4. Visual feedback shows current name length and remaining characters (e.g., "8/12")
5. Pressing Enter with a valid name (1-12 non-empty characters) transitions to gameplay with that name
6. Pressing Escape returns to the title screen without consuming a credit
7. Existing title screen credit system and game flow continue to function unchanged

## Dev Notes

### Previous Story Insights
Story 1.2 (Title Screen) establishes the screen component pattern: class-based with CanvasRenderer injection, show/hide lifecycle, requestAnimationFrame loop, and keyboard event binding. Story 1.3 (Hero Creation) accepts a name parameter in `createHero(name)` and already enforces the 12-character limit with `name.trim().substring(0, 12)`. The name is currently hardcoded as `'Hero'` in `main.ts` line 369.

### Component Architecture
[Source: TitleScreen.ts pattern analysis]
**CharacterNamingScreen.ts Component (`apps/web/src/ui/CharacterNamingScreen.ts`):**
- **Pattern**: Follow TitleScreen.ts class structure exactly
- **Constructor**: Accept `CanvasRenderer` instance
- **Lifecycle**: `show(onNameConfirmed, onCancel)` / `hide()`
- **Input**: Direct `document.addEventListener('keydown', handler)` (no InputHandler.ts exists)
- **Animation**: `requestAnimationFrame` with delta-time for cursor blinking
- **Cleanup**: `cancelAnimationFrame` and `removeEventListener` in `hide()`

**Callback Type:**
```typescript
export type NamingConfirmedCallback = (name: string) => void;
export type NamingCancelCallback = () => void;
```

### Rendering Integration
[Source: CanvasRenderer.ts API]
**Available Drawing Methods:**
- `renderer.clear()` - Clear screen with black background
- `renderer.drawBox(x, y, width, height, color?)` - ASCII border
- `renderer.drawText(text, x, y, color?)` - String rendering
- `renderer.drawChar(char, x, y, color?)` - Single character

**Viewport:** 80 columns x 24 rows (GAME_CONSTANTS.VIEWPORT_WIDTH / VIEWPORT_HEIGHT)

**Color Constants (GAME_CONSTANTS.COLORS):**
- `TEXT_BRIGHT: '#00FF00'` - Title, confirmed name text
- `TEXT_NORMAL: '#00CC00'` - Input text
- `TEXT_DIM: '#008800'` - Instructions, character count
- `HEALTH_CRITICAL: '#FF0000'` - Error feedback
- `UI_BORDER: '#00AA00'` - Box borders

### Integration Points in main.ts
**Current Flow:**
```
showTitleScreen() -> titleScreen.show(startGame) -> startGame()
```

**Target Flow:**
```
showTitleScreen() -> titleScreen.show(showNamingScreen)
  -> namingScreen.show(onConfirm, onCancel)
    -> onConfirm(name): startGame(name)
    -> onCancel(): refund credit, showTitleScreen()
```

**Credit Refund on Cancel:**
When the player presses Escape on the naming screen, the credit deducted by `attemptGameStart()` must be refunded. Use `titleScreen.addCredit()` before calling `showTitleScreen()`.

### Existing Hero Name Handling
[Source: apps/web/src/game/Hero.ts]
- `createHero(name, playerId)` already trims and caps name at 12 chars
- Starting equipment uses hero name: `"${ownerName}'s Dagger"`, `"${ownerName}'s Shirt"`
- GameHUD renders `hero.name` in stats panel

### Performance Requirements
- Screen transition should be instantaneous (no loading state needed)
- Render loop at 60fps for smooth cursor blink
- No API calls or persistence required for naming screen

## Risk Assessment

### Implementation Risks
- **Primary Risk**: Credit deduction timing - credit is consumed in TitleScreen.attemptGameStart() before naming screen shows. Cancel must refund.
- **Mitigation**: Use titleScreen.addCredit() on cancel. Verify credit count before and after cancel flow in tests.
- **Verification**: Test full flow: start with N credits -> enter naming -> cancel -> verify N credits remain.

### Rollback Plan
- Revert main.ts changes to restore direct title-to-game flow
- CharacterNamingScreen.ts is a new file and can be deleted without side effects
- No shared type changes required for this story

### Safety Checks
- [ ] Title screen credit system works identically after changes
- [ ] Game start with named hero produces same gameplay as before
- [ ] Pressing R after game over still returns to title screen correctly
- [ ] Equipment still shows hero name on items
