# Story 2.4: Death Site Teeth Currency Generation

## Status
Ready for Review

## Story
**As a** player starting a new hero,
**I want** to find teeth currency at locations where previous heroes died,
**so that** I can collect resources to purchase better equipment from town merchants.

## Acceptance Criteria
1. Hero death generates 1-32 teeth currency at the exact death location coordinates
2. Teeth remain at death sites permanently until collected by future heroes
3. Teeth display as collectible ASCII symbols (% or similar) on dungeon floors
4. Player can interact with teeth to add them to current hero's currency inventory
5. Teeth collection provides clear visual and text feedback showing currency gained
6. Multiple teeth can accumulate at the same location from multiple hero deaths

## Dev Notes

### Current Placeholder Teeth

`main.ts:120-137` generates random placeholder teeth during level creation. These are marked with a TODO comment referencing this story. The placeholder code:
- Creates 4-8 teeth scaled by dungeon area ratio
- Places them at random floor tiles
- Each has a random value of 1-10

This story replaces all placeholder teeth with death-event-generated teeth. After this story, the first hero in a fresh world will find **no teeth** on dungeon floors -- teeth only appear after a hero has died.

### Existing Teeth Pickup Flow

`main.ts:241-248` handles teeth pickup:
```typescript
const itemIndex = state.items.findIndex(i => i.pos.x === newX && i.pos.y === newY);
if (itemIndex !== -1) {
  const item = state.items[itemIndex];
  state.hero.teethCurrency += item.value;
  state.messages.unshift(`Picked up ${item.value} ${item.name}!`);
  state.items.splice(itemIndex, 1);
}
```

This logic stays mostly the same. The key addition is calling `WorldStore.markTeethCollected()` for persisted teeth so they don't reappear on future visits.

### TeethDrop vs DeathEvent

The `DeathEvent` (from Story 2.2) already includes a `teethDropped` field with the 1-32 random value. Story 2.4 creates a separate `TeethDrop` entity because:
- Teeth have their own lifecycle (created → placed → collected)
- Teeth need spatial data (position on map) separate from the death event record
- Teeth can be collected independently of other death consequences
- The `teethDrops` IndexedDB store indexes by `levelDepth` for efficient per-level queries

### Stacking Multiple Teeth at Same Location

If two heroes die at the same tile, two separate TeethDrop records exist in IndexedDB. When loading into the level, these can be:
- **Option A:** Displayed as separate entities (two `%` symbols stacked -- only one visible)
- **Option B:** Merged into a single entity with combined value

**Recommended: Option B** -- merge at load time. Sum all TeethDrop values at the same `(x, y)` coordinate into one item entity. On pickup, mark all underlying TeethDrop records as collected.
