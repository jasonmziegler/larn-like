### Complete Database Schema
[Source: architecture/database-schema.md]
The database schema includes all required tables with proper relationships:

**Core Tables:**
- **players**: Authentication integration with auth_id, username, credits
- **heroes**: Temporary progression with decimal stats for +0.1 reagent bonuses
- **equipment_items**: Named equipment with blessing support and stat bonuses
- **hero_equipment**: 10-slot equipment system with slot constraints
- **dungeon_levels**: Procedural layouts with JSONB storage and stairs positioning
- **monster_types**: Baseline monster definitions with ASCII characters and spawn weights
- **monsters**: Individual instances with evolution tracking and queue positioning
- **soul_shrines**: Blessing stations with level placement and queue management
- **death_events**: Event sourcing with equipment transfer and world consequence tracking

**Performance Optimizations:**
```sql
-- Performance optimizations
CREATE INDEX CONCURRENTLY idx_monsters_level_active ON monsters(current_level) WHERE queue_position IS NULL;
CREATE INDEX CONCURRENTLY idx_equipment_search ON equipment_items(type, rarity, is_blessed);

-- Views for common queries
CREATE VIEW active_monsters AS
SELECT m.*, mt.name as type_name, mt.ascii_char
FROM monsters m
JOIN monster_types mt ON m.type_id = mt.id
WHERE m.queue_position IS NULL;
```

### Migration System Configuration
[Source: architecture/infrastructure-setup-configuration.md]
**Supabase CLI Setup:**
```bash
# Install Supabase CLI globally
npm install -g supabase

# Login and initialize project
supabase login
supabase init

# Link to remote project
supabase link --project-ref your-project-ref
```

**Migration Workflow:**
```bash
# Create new migration
supabase migration new initial_schema

# Apply migrations to local development
supabase db reset

# Push migrations to remote (production)
supabase db push

# Generate TypeScript types from schema
supabase gen types typescript --local > src/types/supabase.ts
```
