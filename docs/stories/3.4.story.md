# Story 3.4: Monster Equipment Slot Management

## Status
Done

## Story
**As a** system,
**I want** monsters to follow the same 10-slot equipment constraints as players,
**so that** promoted monsters carrying trophy gear remain manageable and don't become overly complex.

## Acceptance Criteria
1. **[CRITICAL BUG FIX]** Promoted monsters persist correctly even when target level doesn't exist yet
2. Monsters use identical 10-slot equipment system as players with same constraints
3. When monster equipment slots are full, overflow items automatically distribute to nearby dungeon chests
4. Monster equipment display in detail panels shows organized slot-based layout
5. Trophy equipment from defeated heroes properly fills monster slots according to item types
6. Monster stat bonuses from equipment calculate using same system as player equipment
7. Equipment slot management handles edge cases (multiple rings, weapon/off-hand combinations)

## Background / Rationale

**CRITICAL BUG:** Story 2.2 introduced a monster promotion bug where promoted monsters are lost if their target level hasn't been generated yet (`DeathProcessor.ts:369-381`). This causes "4 heroes fallen, 0 monsters evolved" scenarios where all promotions are discarded. This story fixes this critical persistence bug as part of monster management improvements.

Stories 2.3 and 2.9 established monster equipment transfer (single trophy system), but monsters need full 10-slot management to:
- **Fix promotion persistence:** Store promoted monsters until target level is generated (CRITICAL)
- **Prevent over-gearing:** Limit monster equipment to 10 slots (same as heroes)
- **Enable overflow:** Gracefully handle excess equipment via chest spawning
- **Maintain balance:** Ensure monster power scales predictably
- **Support inspection:** Allow players to see exactly what monsters are carrying

This story enforces equipment parity between heroes and monsters, ensuring the persistent world system remains balanced as monsters accumulate trophies across multiple hero deaths.

### Monster Effective Stat Calculation

```typescript
function getMonsterEffectiveAttack(monster: Monster): number {
  const baseAttack = monster.attack;
  const equippedItems = getEquippedItems(monster.equipment);
  const equipmentBonus = equippedItems.reduce((sum, item) => sum + item.attackBonus, 0);
  return baseAttack + equipmentBonus;
}

function getMonsterEffectiveDefense(monster: Monster): number {
  const baseDefense = monster.defense;
  const equippedItems = getEquippedItems(monster.equipment);
  const equipmentBonus = equippedItems.reduce((sum, item) => sum + item.defenseBonus, 0);
  return baseDefense + equipmentBonus;
}
```

```typescript
// WorldState.ts - Add pending promotions storage
export interface LocalWorldState {
  version: number;
  credits: number;
  currentHero: Hero | null;
  deathEvents: DeathEventRecord[];
  levels: DungeonLevelRecord[];
  pendingPromotions: MonsterRecord[]; // ← NEW
  lastSaved: string;
}

// DeathProcessor.ts - Store or inject promoted monster
const targetLevel = worldState.getLevel(newLevel);

if (targetLevel) {
  // Level exists - add promoted monster immediately
  const updatedMonsters = [...targetLevel.monsters, promotedMonster];
  await worldState.saveLevel({ ...targetLevel, monsters: updatedMonsters });
} else {
  // Level doesn't exist - store for later injection
  await worldState.savePendingPromotion({
    ...promotedMonster,
    targetDepth: newLevel, // Track which level this monster belongs to
  });
}

// DungeonGenerator.ts or level loading - Inject pending promotions
async function loadOrGenerateLevel(depth: number): Promise<DungeonLevelRecord> {
  let level = worldState.getLevel(depth);

  if (!level) {
    level = generateNewLevel(depth);
  }

  // Inject any pending promotions for this depth
  const pendingForThisLevel = await worldState.loadPendingPromotions(depth);
  if (pendingForThisLevel.length > 0) {
    level.monsters = [...level.monsters, ...pendingForThisLevel];
    await worldState.saveLevel(level);

    // Clean up injected promotions
    for (const monster of pendingForThisLevel) {
      await worldState.deletePendingPromotion(monster.id);
    }
  }

  return level;
}
```

### Edge Cases to Handle

1. **Monster with 10 items receives new trophy:** All hero items → overflow chest
2. **Monster has ring1 filled, hero has 2 rings:** Random selection picks one ring
   - If selected ring slot is full → overflow
3. **Two-handed weapon on monster:** Blocks off-hand slot (same as hero)
4. **Promoted monster moves levels:** Equipment persists via MonsterRecord
5. **Pending promotion to ungenerated level:** Store in pendingPromotions, inject on level creation (Task 0 fix)
