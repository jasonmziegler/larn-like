# Story 2.6: New Hero Integration with Persistent World

## Status
Done

## Story
**As a** player creating a new hero after death,
**I want** to enter a world shaped by my previous heroes' deaths,
**so that** each new attempt feels meaningfully different due to accumulated world changes.

## Acceptance Criteria
1. New heroes spawn with fresh base stats but enter the persistent world state
2. Dungeon levels reflect all previous monster promotions, teeth drops, and equipment distributions from this browser's history
3. Heroes can immediately encounter evolved monsters and collect teeth from previous deaths
4. Local world state loads and reflects accumulated changes from previous sessions
5. New hero creation process accounts for available credits and maintains "Insert Coin" flow
6. Clear visual/text indicators help players understand which elements are persistent vs. reset

### Current Game Flow (Implemented)

```
init()
  └─ WorldState.initializeWorld() → load from IndexedDB (main.ts:751-763)
       └─ showTitleScreen()
            └─ [ENTER] → showNamingScreen()
                 └─ [name confirmed] → startGame(heroName, worldState)
                      └─ initGame(heroName, worldState) → creates hero, loads persistent entities
                           └─ game loop (saves on key events)
                                └─ on death: DeathProcessor → save to IndexedDB
                                     └─ [R] → showTitleScreen() (world persists)
```

### Implementation Notes

**Credits Sync Pattern:**
- TitleScreen uses localStorage as fast-access cache
- WorldState manages IndexedDB as source of truth
- Callback pattern keeps them synchronized (main.ts:774-779)

**Level Loading:**
- LevelManager handles level generation and persistence
- On first visit: generates fresh level with baseline monsters
- On revisit: loads persisted level with evolved monsters, teeth, chests
- Entities placed at persisted positions on the dungeon grid

### Dungeon Layout Persistence

**Design Decision:** Dungeon layouts are NOT persisted. Each new hero gets a freshly generated layout, but **entities persist** (evolved monsters, teeth, chests). Entities are stored with their dungeon grid positions and reload at those exact coordinates. The LevelManager handles level generation vs. loading logic.

### Reset World Feature (Implemented)

Accessible via **Shift+Enter** on the character naming screen:
- Deletes entire IndexedDB database
- Resets credits to default (3)
- Reinitializes fresh world state
- Shows "World reset! Starting fresh..." message for 2 seconds
- Implementation: CharacterNamingScreen.ts:124-148
