# Story 2.8: Soul Shrine Blessing Interaction

## Status
Done

## Story
**As a** player exploring the dungeon,
**I want** to interact with soul shrines to attempt to bless my equipment,
**so that** I can gain powerful enhancements by leveraging the legacy of fallen heroes.

## Acceptance Criteria
1. Player can interact with a shrine when adjacent by pressing a designated key
2. Interaction presents a choice of which equipped item to attempt to bless
3. Blessing outcome is chance-based: success enhances the item's stats, failure may degrade or destroy it
4. Success chance influenced by shrine soul energy value and item rarity/tier
5. Used shrine is consumed (removed from world state) regardless of blessing outcome
6. Clear visual and text feedback communicates blessing result to the player

## Dev Notes

### Blessing Chance Formula

```typescript
function calculateBlessingChance(soulEnergy: number, item: EquipmentItem): number {
  const baseChance = 0.40;
  const energyBonus = soulEnergy * 0.005;
  const itemPenalty = (item.attackBonus + item.defenseBonus) * 0.03;
  return Math.min(0.90, Math.max(0.10, baseChance + energyBonus - itemPenalty));
}
```

**Example chances:**
- Energy 40, Dagger (+2 ATK, +0 DEF): `0.40 + 0.20 - 0.06 = 0.54` (54%)
- Energy 66, Dagger (+2 ATK, +0 DEF): `0.40 + 0.33 - 0.06 = 0.67` (67%)
- Energy 40, Blessed Dagger (+5 ATK, +0 DEF): `0.40 + 0.20 - 0.15 = 0.45` (45%)
- Energy 10, Shirt (+0 ATK, +1 DEF): `0.40 + 0.05 - 0.03 = 0.42` (42%)

This creates a risk/reward dynamic: blessing strong items is harder, and low-energy shrines are riskier.

### Stat Enhancement Formula

```typescript
function calculateBlessingBonus(soulEnergy: number, item: EquipmentItem): { stat: 'attack' | 'defense'; amount: number } {
  const isWeapon = item.slot === 'weapon' || item.slot === 'offHand';
  if (isWeapon) {
    return { stat: 'attack', amount: Math.min(3, Math.ceil(soulEnergy / 30)) };
  } else {
    return { stat: 'defense', amount: Math.min(2, Math.ceil(soulEnergy / 40)) };
  }
}
```

**Example bonuses:**
- Energy 40, weapon: `ceil(40/30) = 2` → +2 ATK
- Energy 66, weapon: `ceil(66/30) = 3` → +3 ATK (max)
- Energy 40, armor: `ceil(40/40) = 1` → +1 DEF
- Energy 10, armor: `ceil(10/40) = 1` → +1 DEF (minimum useful)

### Failure Outcomes

Two failure tiers create meaningful risk:
- **Degradation (90% of failures):** Item loses 1 point from its primary stat. A Dagger with +2 ATK becomes +1 ATK. Already at +0 stays at +0 (no negative stats).
- **Destruction (10% of failures):** Item is completely destroyed. The equipment slot becomes empty. This is the high-stakes risk that makes blessing decisions meaningful.

### Blessing Panel Pattern

Follow `InventoryPanel` overlay pattern:
- Class with `render()` method drawing on CanvasRenderer
- Toggled by `b` key in main.ts
- Stored as nullable reference (null = closed)
- Suppresses other input while open
- Number keys select items, ESC closes

### Item Naming After Blessing

Items can accumulate blessing attributions:
- Original: `"Sarah's Dagger"`
- After blessing: `"Sarah's Dagger (Blessed by Bob)"`
- After second blessing: `"Sarah's Dagger (Blessed by Bob, Carol)"`

Keep names reasonable — if more than 3 blessings, truncate: `"Sarah's Dagger (Blessed x4)"`

### EquipmentItem Interface Note

The current `EquipmentItem` interface (`hero.types.ts`) does not have `isBlessed` or `blessedBy` fields. The architecture `data-models.md` defines these fields on the full `EquipmentItem` model but they are not yet in the shared types.

**Recommended approach:** For this story, track blessing state through the item name (append blessing text) and stat changes. Adding `isBlessed`/`blessedBy` fields to the shared type can be done in this story or deferred to a type cleanup story.
